# EM-005：一廠分類、限值反色與括號備註 CFU

日期：2026-10-02。負責修改及GitHub備份：原 Luna 6.0 Max 分支視窗。PM只開工單、調整目標與獨立驗收。

## 使用者已確認的需求

1. 房間 C01～C06 屬一廠，包含 C06D 等字母子房間；一廠篩選及分類必須看得到。
2. 只有不符合 Alarm Lv 標準才反黃，不符合 Action Lv 才反紅；Action 優先。取消「只要數值大於0就反黃」。

5. 程式、工單、測試及驗收紀錄放至 `JackTzeng/Environmental_Monitoring_Domain_Data_Model` 做GitHub版本備份。

## 實作邊界

沿用Flask、SQLite、既有匯入／重新解析、固定程式規則及簡單可檢視對照。禁止LLM判值、架構替換及為本切片增加其他平台。PM不代寫實作。

### A. 一廠分類及既有資料

- 用簡單明確的房間規則識別C01～C06及字母子房間（至少C06D）；不把C00、C07、C060、C16或未知房間歸一廠。
- 檔案有明確廠別時優先；其次使用明確選取的廠別脈絡／已保存的單一廠別資料夾脈絡；都缺少時才依使用者確認的房間規則補一廠。房間／來源／脈絡相矛盾時留原值並明示待核對，不默默覆蓋。
- 處理81個舊來源已保存的source_prefix，不能只補未來手動選site_context的匯入。對照列可用明確整份報告／資料夾廠別，房間仍不硬填。不要因房間推導把未確認的其他房间歸廠。
- 新匯入、一廠篩選、矩陣群組、月格連結、逐筆詳情及CSV廠別須一致，不能只在畫面套名稱而資料庫仍空白。

### B. 限值反色

對該月最早採樣日代表紀錄的目前結果，使用**同筆來源／同次採樣**的alert_raw及action_raw判斷，禁止取全年集合、下一月或另一採樣的限值。

| 原文標準 | 不符合條件 |
|---|---|
| `<5`／`＜5`／`< 5` | 數值 >=5 |
| `<=5`／`≤5`／`≦5` | 數值 >5 |
| 裸數字 `5`（最大允許值） | 數值 >5 |
| `0` | 數值 >0 |

支援現有全部格式（含NA、空白、`< 13`／`< 1`）及上列明確邊界；保留限值原文，不自動換單位。未知格式給可檢視提醒，不以隨意抓首數方式硬判。

- 正常範圍無黃／紅底。超Action用紅底，否則超Alarm用黃底。Alarm不適用時仍可按有效Action判紅；缺失／未知的限值不能等同0。
- 同最早日結果／限值衝突時顯示「需核對」，不給假正常或超限結論；衝突提示採中性樣式，不能讓黃紅色另代表衝突。
- 其他月份／後日限值改版不反改本月顏色。年度限值仍可並列展示，但月格或提示能查實際使用哪筆日期、來源與限值。
- 不只靠顏色傳達狀態：提供簡短圖例及可讀的正常／警戒／行動／待核對文字或提示。
- 檢查輸出頁既有positive黃底；月CFU加總不能直接拿單次採樣限值比較，也不能只因加總>0反黃。本切片不改月報統計口徑。
- 更新與實作不符的「尚不自動判定限值」說明，文字反映這次按來源限值提供顏色提示。

### C. 整數總菌數與括號備註

- 第一版至少支援本庫mold／molds／satellite備註：`3(1mold)`、`8(1mold)`、`1(mold)`、`94(3白mold)`、`109(1 mold)`、`47 (3molds,2白,1黑)`、`15(1satellite)`、`9(1Satellite)`，並處理全形括號及合理空白。
- 只認完整非負整數前綴＋受支援的單組括號備註。總CFU取前段，括號數字不加、不減、不串接；其他不明格式仍待核對，不能搜任意數字。
- `result_raw`及來源原文保持可查；例如`3(1mold)`保留、result_type=count、cfu_count=3。矩陣可保留原字面呈現，趨勢和限值比較取3。不要把mold自動塞成菌種鑑定結果。
- `TNTC(mold)`仍是不可計數，CFU留空；TNTC、`<1`、N/A、缺值、負數及未知文字不偽裝成0或一般CFU，合理的無資料／不可計數缺口仍保留。
- 解析、矩陣、限值判色、趨勢及已確認月報使用一致的CFU值，避免畫面臨時抓數字與資料庫分歧。既有人工CFU修正／核對值不得被原文前綴覆蓋。

### D. 重解析與版本

- parser升版，沿用已驗收reparse_source保護：來源SHA及逐列source_location對應、original及初始版本保留、先備份、人工修改（即使後來改回original）／checked／not_applicable／confirmed／void保護、條件更新0筆整批回滾、同版no-op。
- 修正必須能處理已入庫資料。單純再次匯入資料夾會SHA略過，不算完成。本次交付包含一次可檢視的批次重解析受影響來源流程，使用既有函式；不要要求使用者逐一放Word或逐筆改1188列。不必增加新的工作管理架構。
- 刷新目前site未取得／結果unknown提醒，舊提醒保留在before歷程。維持draft及逐欄pending，不把程式補讀算人工核對或正確率100%。
