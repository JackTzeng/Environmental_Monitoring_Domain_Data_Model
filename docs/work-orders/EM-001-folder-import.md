# EM-001：整個資料夾自動匯入資料庫

負責實作：Luna 6.0，Max。主對話僅負責需求、範圍調整與驗收。

## 使用者要得到的結果

在「輸入」頁指定一次資料夾，按「匯入整個資料夾」，系統自行讀取 Word 與子資料夾，把解析結果直接存進本機 SQLite。不得要求使用者逐一選檔，或逐筆確認後才入庫。

資料必須可檢視、可修正；人工核對用於修正與量測欄位辨認正確率，不作為匯入資料庫的前置步驟。

## 本切片範圍

- 支援本機資料夾及有權限的 Windows 公司共用資料夾（UNC），遞迴讀取子資料夾。
- 預設批量讀取 `.docx`；可選擇一併讀取 Google Sheet 匯出的 `.xlsx`／UTF-8 `.csv`。保留現有多檔上傳及人工新增。
- 直接寫入目前系統資料庫，不另建第二份資料庫。保留來源副本、雜湊、原文、解析版本及修改歷程，不改寫來源。
- 同一內容重跑不增加重複資料、不覆蓋人工修正；不同檔案的同採樣候選沿用目前對帳提醒。
- 顯示掃描／已處理進度，以及新增檔案、新增明細、已存在、失敗數與失敗原因。單檔失敗後繼續下一檔，不得把失敗顯示為成功。
- 跳過 Office 暫存檔與不支援格式；避免連結／junction 導致遞迴循環。大批量匯入不受上傳頁的整批 25 MB 限制，仍需單檔大小保護。
- 長任務期間頁面可查看進度；同時重複啟動需防止。程式中断後可重跑，利用既有內容雜湊避免重複。
- 匯入即入庫的狀態與月報採用的核對狀態須清楚顯示。沿用月報只納入已確認紀錄的目前規則，不自動勾選逐欄核對或製造正確率。

本次不增加 LLM、工時分析、QA 簽核流程、Google 線上授權、排程監看或多人部署。

## 驗收案例

| 編號 | 操作 | 通過條件 |
|---|---|---|
| A1 | 指定含多份 Word 的資料夾，含至少兩層子資料夾 | 一次操作全部處理，明細直接存在資料庫，無逐檔選擇。 |
| A2 | 對同一資料夾再次執行；其中一筆已人工修正 | 新增數為 0；既有原值、修正及歷程保持。 |
| A3 | 資料夾混有壞 Word、暫存檔及合法 Word | 合法檔仍入庫；壞檔有檔名與原因；暫存檔跳過；結果數可對帳。 |
| A4 | 選擇不存在、無權限或非資料夾路徑 | 明確錯誤，沒有假成功或資料遺失。 |
| A5 | 選擇一批總量超過 25 MB 的合法檔；再次點啟動 | 批次可處理；單檔保護有效；第二次啟動不造成兩份任務或重複明細。 |
| A6 | 勾選／取消 Sheet 匯出檔選項 | 勾選時包含 XLSX／CSV；取消時僅 Word。 |
| A7 | 在資料庫檢視一筆匯入值與來源，開啟正確率及月報 | 原文與目前值可查；未人工核對仍顯示待核對／未評估；既有報表規則不改變。 |

以暫存測試資料完成自動測試與 GUI 驗證；不要自行把整個公司歷史資料灌入正式資料庫，也不要刪除目前使用者資料。實際公司資料夾由使用者在介面指定。
