# EM-003：修正真實 Word 漏欄位與舊匯入重新解析

負責實作：同一個 Luna 6.0 Max 對話。PM 僅做來源比對、目標調整及驗收，不代寫程式。

## 問題與驗收基線

使用者實際驗收三廠 2026 年 6 月資料夾，發現很多缺值。PM 已唯讀核對七份 Word；未修改公司來源或正式資料庫。

解析器 0.1.1 產生142列：133筆監測點位、7筆對照、2筆非資料。檔案讀取成功不等於欄位正確；兩筆非資料應被排除。

現有正式資料庫仍是38筆、1個Air來源、原始解析版本0.1.0。房間38筆全空；同內容重匯入被視為duplicate，單純升级解析器無法修復已入庫資料。

以上是已證實的空值／漏讀數，不是全歷史的辨認正確率。公司原始檔只在本機／公司共用資料夾讀取，不上傳 GitHub；真實資料位置已在主對話與實作對話提供。

## 必須修正的規則

1. 正確辨識已證實的 `▓培養皿接觸法` 勾選；仍保留未勾、多勾與模糊值的提醒，不因欄位列出選項就全選。
2. 拆分明確房間點位，例如 `C11_BSC01-1` → 房間C11／點位BSC01-1；`C11_GTP1：P06(上)` → 房間C11／點位P06(上)。上／下等後綴必須保留，不能合併成同一點位。保留来源原文。
3. `GTP7：BSC07-01-1` 類型不可憑字串猜房間。PM已從使用者參考XLSX「三廠｜落菌法」核對15個點位：BSC07系列屬C17，BSC08系列屬C18。建立簡單、可人工檢視／維護的明確對照，限於有來源根據的廠別與範圍；保留對照依據，未知對照繼續待處理，不擴大套用到其他廠別或無證據歷史版本。
4. 無塵衣：`■培養皿接觸` 標準化為培養皿接觸法；支援原文 `批次編碼`；保留 `■無塵衣月監測` 的無塵衣類型，不能混成例行環測。沒有廠別专欄時可採匯入明確廠別／資料夾脈絡作後備，記錄依據，與原文衝突時不得默默覆蓋。
5. 排除無塵衣 `-以下空白-` 與只有未勾選 `□合格 □不合格`、採樣欄皆空的尾列；不要因整列有文字就建立採樣。真正採樣但缺結果仍需保留，不能一律丟棄空結果列。
6. 區分「來源未提供／此類型不適用」與「來源有值但解析漏讀」。例行報告的檢驗人員不能塞成操作者，未提供菌名不能猜菌名；對照與無塵衣身體位置不硬填房間。無塵衣 `標準(CFU)` 不等於Alert或Action分欄，保留原文並清楚可見，不自行指定限值類別。未人工核對不得自動勾為正確。

單位核對：七份Word結果欄都寫 `結果(CFU)`，PM未找到明確CFU/m3或CFU/m³；本工單不要求一律改成CFU/m³。來源未寫的內容不能從參考報表的單位反推。

## 舊資料重新解析

新增清晰可操作的重新解析入口，讓使用者能修復已匯入的舊版擷取結果，不需刪除資料庫、改名檔案或反覆匯入。

- 來源內容SHA相同時仍不增加重複採樣；重新解析是不同於「再次新增匯入」的動作。
- 原始匯入值／版本、來源副本及既有人工修改完整保留；保存新版解析與變更依據／歷程。
- 自動更新僅限未經人工更改或核對的欄位。人工修正值、已核對欄位與已確認狀態不得被默默覆蓋；有差異可列出供核對。
- 先備份，並使用既有版本衝突保護；重跑同版本不重複新增或製造假修正。
- 新规则判定舊列為非資料時，保留可追溯紀錄與處理理由，不硬刪使用者資料。
- 不把程式補讀算成「人工核對成功」；每欄正確率仍以保留的辨認值與人工參考值計算，清楚標示解析版本。

| 編號 | 操作 | 通過條件 |

| C2 | 核對Contact與明確房號BSC點位 | 26筆方法正確；8筆上／下後綴保留；30筆明確BSC房間正確拆分；對照不硬補。 |
| C3 | 核對GTP7／8 BSC對照與未知案例 | 15筆有參考根據的對照正確；跨廠、未知點位或無根據版本不套用。 |
| C4 | 核對無塵衣6個有效資料列 | 方法、類型、批次與有根據的廠別可讀；標準原文可查；房間／菌名／操作者缺來源時明示，不誤填；兩尾列排除。 |
| C5 | 暫存DB先用舊版解析匯入，人工改一欄，再重新解析 | 補回未核對漏欄；保留原始值／舊版與人工修正；不增加重複採樣；改動有原因與版本，先有備份。 |

| C7 | 回資料庫矩陣與逐欄正確率 | 修正後目前值可見；來源未提供、待對照、未人工核對可區分；沒有將補讀當人工核對或正確率100%。 |

沿用同一程式與既有資料庫，以固定規則與簡單對照維護。禁止LLM解析、猜值、資料庫重建或大架構替換。本切片不新增工時或QA簽核門檻。

先在獨立暫存資料庫驗證重新解析。真實Word可唯讀跑解析並列結果；不要自行整批灌入正式資料庫。交付新解析版本、針對測試、真實檔欄位核對結果及實際GUI證據；正式資料缺值問題在本工單通過前不得宣稱驗收完成。
