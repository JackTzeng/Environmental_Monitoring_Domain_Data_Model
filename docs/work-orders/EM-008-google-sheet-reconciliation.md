# EM-008：管理者 Google Sheet 核對與缺欄補值

日期：2026-10-02。沿用 EM MVP 的 Flask／SQLite 與逐欄人工核對，不另建資料庫、不回寫 Google Sheet、不做雙向同步或排程。

## 來源範圍與讀取方式

- 僅讀「三廠管理者更新」（sheetId 0，固定套用三廠來源脈絡）及「一廠管理者更新」（sheetId 526085303，固定套用一廠來源脈絡）。其他分頁即使同一本 workbook 內可見，也不讀其內容。
- 由輸入頁提供「Google Sheet 核對／補資料」；使用者每次按下讀取才抓取固定兩分頁。連接器讀取權不視為本機程式已取得 Google 授權。
- 本機直連採 Google Sheets API 唯讀 scope 與一般本機 OAuth；OAuth 用戶端設定及 refresh token 只留在本機資料目錄／環境設定，不寫入 Git。沒有有效授權時明確提示如何設定及授權，不假稱直連已驗收。
- 下載的 XLSX 使用同一份兩分頁 adapter，精確按分頁名稱讀取，跳過其他分頁內容。兩種來源都保存完整目標列、sheetId、分頁、儲存格列範圍、讀取時間及目標分頁快照 SHA-256。

## 欄位與採樣分群

- A 文件控制欄不當成採樣。B 保留來源識別原文，不解析成日期。採樣日只由 C 年、D 月、E 日組合並嚴格驗證。
- F 方法、G 目的、H 檢驗批次、I/J 操作者、K 房間／科室、L Grade、M 點位、N 總菌數、O 菌落數；S:Y 菌鑑資料留在採樣子列證據，不增加採樣筆數或 CRR 分母。P 與 R 的 PA／AL／AC／Fail 等只作來源分類文字，不當數值限值、不自動排除或改變陽性。
- G 只把明確設定中的「環測」及「汙染後環測」映射到對應監測類型；IC、ADCV、BMSC、GDT、TC 等產品目的保留原文，未有明確對照前列待分類，不推猜成製程或例行環測。
- 以日期、廠別脈絡、方法、點位、房間與 B/H 等來源識別欄建立候選採樣群。B 相同但其他採樣欄不同、B 空白、同日重採、關鍵欄衝突或群組不唯一均列待核；不能以 B 單欄合併，也不能因同一列有多個菌鑑子列而複製樣本。
- 對每個群組先核對完整快照及所有子列。N 有唯一一致數值才作總 CFU；多個不同 N 值衝突。N 空白、O=0 僅在完整快照確認為單一採樣、沒有其他菌種子列且無矛盾時補候選 0，並保留「N 原空白／O 明確 0」證據及規則註記。N 空白／O 正數、重複 N、截斷快照或群組不完整都留待核，不補 0。
- I/J 兩位操作者同時存在時保留兩人及原列，但一個培養皿仍為一筆採樣；人員 CRR 歸屬待人工核對，不任選一人、不複製樣本或人日。

## 與 Word 的核對與更新

- 用日期／廠別／方法／點位／房間做第一階段候選，再核批次、Grade、單位及人員。既有 `candidate_key` 只提示候選，不能直接視為唯一鍵。
- Word 唯一匹配且值一致：一致略過；唯一匹配但 Word 欄位空白：提出逐欄補值候選；兩側非空值不同或候選不唯一：列差異／衝突；沒有 Word 匹配：列 Sheet 新 draft 候選。正式統計仍依現有 state 與分析納入旗標。
- 完全相同快照不得重複；新快照以穩定採樣身分更新候選或只新增可唯一識別的新採樣，不受列排序影響。API 與 XLSX 來源重疊、或與 Word 已有樣本相同，都不能重複採樣／重複零值。
- 採用合格補值須使用資料版本檢查與寫入前備份，只填仍空白且未人工修改／核對欄位。每欄保存原值、新值、原因與 Sheet 儲存格證據；刷新、重匯不得覆蓋人工修正、verified、state、分析排除。刪列只提示，不刪原紀錄。排除狀態不因 Sheet 更新而恢復。
- 新候選先維持 draft；不得自動 confirmed、void、排除或恢復納入。保留樣本總 CFU與菌種子列之分，Sheet 子列不增加採樣統計。

## 驗收

- 使用與 Word 重疊月份的兩廠真實目標分頁做唯讀端到端核對；不寫正式 DB。
- 合成回歸覆蓋多菌種分組、N 空 O=0 的嚴格完整性條件、N 空 O 正數、N 衝突、多操作者、同日不同 B 重採、相同 B 不同日期／方法／點位、B 空白、非唯一 Word 候選、相同快照、列重排、新快照及 API/XLSX/Word 重複、人工／核對／排除保護、Fail 保留、非指定分頁不讀、取消或失敗快照不得採 0。
- 每欄只以實際 checked 分母計正確率；未核對顯示「未評估」，有值率及配對率不是正確率，人工新增不計 parser accuracy。
- 匯入頁顯示讀取範圍、樣本數、菌種子列數及一致／補值／衝突／新 draft／待核對數，提供來源證據、差異檢視、合格補值批次採用及清楚錯誤訊息。
- 遵守檔案與啟動政策；若合法本機 OAuth 尚未設定，交付 OAuth 設定提示與相同 adapter 的 XLSX 路徑，不宣稱 Google 直連已通過。
- 程式、測試、工單及無真實公司明細的驗收摘要分別交 PM 覆驗。PM 接受後再按授權正常提交及推送既有分支；不提交真實 Sheet 列、公司來源、資料庫、OAuth token／client secret 或 log。
