# EM 簡單版 MVP

本版採清晰程式碼驅動，不使用 LLM。目標是可檢查的 INPUT → DATABASE → OUTPUT；先完成單人資料核對與月報，不先建立完整 GMP 正式紀錄系統。

## 三個畫面

| 畫面 | 操作與結果 |
|---|---|
| INPUT | 選擇本機 Word 或 Google Sheet 匯出檔，顯示讀取筆數、來源位置與解析例外。 |
| DATABASE | 篩選明細、比對原文、核對各欄位；修正擷取值須填原因，保留前後值。 |
| OUTPUT | 選擇廠別與月份，僅以已確認紀錄產生人員 CRR、點位月份矩陣及月份趨勢；呈現特殊結果排除數，另列逐欄正確率與待核對數。 |

Word、Sheet 匯出檔只讀，不改寫來源。Google Sheet 首版透過 XLSX／CSV 匯出檔輸入；不要求公開資料或保存帳密。

資料庫保留來源檔雜湊、表格／列位置、擷取原文、解析規則版本與修正紀錄；尚無逐欄來源位置。同內容檔案重跑不新增、不覆蓋已核對修正；不同檔案的同採樣候選仍須人工處理。

空白、0、TNTC、`<1`、N/A 分開保存；不能全部轉成 0。未知版型、缺欄位與衝突列為待處理，不能猜值。菌名有來源就保留，菌相趨勢待資料足夠後加入。

## 正確率與核對

MVP 不要求先取得 QA 簽核的黃金資料集，但仍需人工逐欄核對的參考值；沒有參考值就不能宣稱正確率。

- 每欄記錄「未核對、已依來源核對、不適用」；確認紀錄狀態與逐欄核對狀態分開，未檢查欄位仍列待核對。
- 欄位級解析正確率＝凍結的原始辨認值與目前人工核對值相符數／已核對適用欄位數，逐欄顯示正確、錯誤及待核對數。
- 修正後仍比較原始辨認值，不另算修正後正確率；人工新增、作廢及不適用欄位排除。無已核對分母時顯示「未評估」。
- 正確率表涵蓋選定廠別的全部月份，不受月報期間篩選；CSV 可匯出全廠數據。目前未提供全公司歷史檔案覆蓋率。
- 月報只納入已確認狀態資料，不預覽待核對資料；產出仍為分析草稿。歷史核對逐步擴大至最舊版型及異常結果，矩陣差異回到來源核對。

## 指標候選定義

| 指標 | 本版範圍與口徑 |
|---|---|
| 採樣資料 | 已計算可計數採樣數、CFU 加總與陽性數；矩陣顯示採樣數及CFU，GUI 尚未另呈現採樣陽性率。 |
| 報告事件 CRR | 後續候選，尚未實作；陽性報告事件數／有效報告事件數，仍需定義事件識別與納入規則。 |
| 人員人日 CRR | 同廠、同人、同日的 Grade A 製程監測，落菌與培養皿接觸法合併；任一點位 CFU > 0 為陽性人日／有效監測人日數。 |

人員報表沿用既有報表的人日候選口徑；採樣、報告事件、人日不能混用。同人日任一納入點位為非數值結果，整個人日排除並列出排除數。期間比率取總分子／總分母，不平均月百分比；無有效分母顯示「—」。

缺姓名與 Isolator 不強行加入人員 CRR；保留在相應點位資料或待核對清單。點位矩陣按同方法、同單位呈現 CFU 加總及採樣筆數；無採樣與採樣結果 0 分開。

上述口徑供使用者核對，MVP 不以 QA 簽核為前置要求。正式 GMP 用途前依公司程序處理；限值及等級生效日期管理尚未實作。資料庫月矩陣會以每月最早採樣日代表紀錄同筆來源的 Alert／Action 原文顯示超限提示：超 Action 紅色、否則超 Alarm 黃色；未知或缺漏限值與同日衝突顯示中性待核對。該提示不取全年限值，不改月報加總口徑，也不是正式簽署。

## 六項審查問題的目前答案

| 問題 | 答案 |
|---|---|
| 正式紀錄還是分析資料？ | 暫定為可重建的衍生資料與草稿報表；正式來源地位依公司 SOP，尚非 QA 已批准的定位。 |
| 全歷史欄位正確率？ | 尚未知；檔案讀取成功及資料量不等於正確率，以人工參考值量測。 |
| 舊矩陣不一致如何裁定？ | 舊矩陣僅作參考，回到來源逐筆確認；來源矛盾由使用者／紀錄負責人裁定並留理由，未裁定不得視為正確。 |
| CRR 分母誰簽核？ | MVP 先由使用者確認書面候選口徑；正式品質用途由資料負責人與 QA 依公司程序批准，尚無簽核證據。 |
| 只有解析器與例外清單的效益？ | 可省重複抄錄與彙總，但目前未量測效益；不提供沒有證據的工時或百分比。 |
| 參考專案授權？ | 兩者在已查核版本未找到 LICENSE；僅參考一般呈現構想，自行實作，不複製工作簿、程式、圖檔或資料。 |

授權與查核版本詳見 [REFERENCE-PROJECTS.md](../REFERENCE-PROJECTS.md)。

修正擷取錯誤是使資料符合原文；發現原文事實有錯，先保留待核對狀態與處理原因，依公司程序更正來源，不能只改資料庫讓兩邊分歧。

## 維護與後續多人使用

首版在單一電腦啟動，瀏覽器只連 localhost，SQLite 檔留在本機。SQLite 不放網路共用資料夾讓多台電腦直接開啟；寫入前建立 SQLite 備份，來源與程式另保留。完整還原演練尚未完成。

多人版改成公司核准的中央服務，由瀏覽器存取；再加入認證、權限、修改衝突檢查及集中備份。SQLite 可由單一服務程序存取，是否改資料庫引擎依實際並行寫入與維運需求決定，不預設 PostgreSQL。

本版不宣稱防竄改稽核軌跡、電子簽章或 GMP 確效完成。衍生報表若實際用於品質決策，仍需適用性及風險評估；正式上線要求留待 QA／IT 定案，不以「分析輔助」免除資料完整性責任。[Annex 11](https://health.ec.europa.eu/document/download/8d305550-dd22-4dad-8463-2ddb4a1345f1_en?filename=annex11_01-2011_en.pdf)、[FDA Part 11 適用性指引](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/part-11-electronic-records-electronic-signatures-scope-and-application)。
