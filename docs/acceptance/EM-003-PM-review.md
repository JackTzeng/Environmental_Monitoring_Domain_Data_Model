# EM-003 PM 獨立驗收：退回修正

日期：2026-10-02。受驗版本：app 0.3.0／parser 0.1.2。主對話僅驗收，未修改應用程式或正式資料。

## 判定

指定來源的 C1、C2、C4 符合交付；C3、C5、C6、C7 尚未通過。44 項既有測試重跑全數通過，但未涵蓋以下独立復現的缺陷，因此不能據此批准整張工單。

七份真實 Word 只讀重跑為38／26／16／16／31／7／6，共140列（133監測、7對照），兩尾列排除。逐列檢查日期、Grade、原始結果、CFU、點位、房間與提供的限值，未發現指定來源的欄位錯位；方法26筆、上下後綴8筆、明確BSC房間30筆及限定對照15筆符合來源／參考。這是指定來源驗收，不是全歷史辨認正確率。

正式資料庫仍為38筆、1來源、0筆變更，來源原始及目前解析版本皆0.1.0。原始紀錄摘要 SHA-256 與先前基線相同：`ed8e3da362f5e25524333db6906fdd48d19b6b376a02d3ee08e602e9cde99a77`。未在正式库執行匯入或重新解析。

## 必須修正的五項缺陷

1. **C5：修改前值不實。**在獨立暫存DB以原始room空白重新解析成C11，歷程before.current.room及after.current.room都成為C11。before與待修改current共用字典。應在改值前保存独立快照，涵蓋全部前後欄位，不只room。
2. **C5／C6：版本衝突後假成功。**在重解析讀取紀錄後、條件UPDATE前插入一次既有store.update人工儲存，當時尚未建立寫入交易。重解析條件UPDATE實際0筆，仍回報updated=1、寫補值歷程並升source版本；實際room仍空，重跑同版卻no-op。必須使失敗更新回滾／明確衝突，不留下假成功歷程或升版；對所有條件UPDATE處理一致。
3. **C7：過期缺值警示混入目前狀態。**原room空白且警示room:未取得，補成C11後record頁仍在頂部顯示同一缺值警示，沒有原始／目前區分。原警示可留在原始歷程，但目前提示應反映目前解析與受保護人工值，不能暗示已補欄仍缺失。
4. **C5：新增列的初始解析版本錯標。**原來源0.1.0，重解析0.1.2新產生row3的original.room=C12；該列頁面及CSV卻標原始parser0.1.0。需保留來源首次匯入版本，同时正確記錄／呈現每筆辨認值首次生成的版本，不能將0.1.2辨認值归到0.1.0。
5. **C3：參考對照覆蓋明確來源，且忽略前綴矛盾。**三廠、2026/06/03、落菌法，來源明寫room=C99及point=GTP7：BSC07-01-1，結果room被覆蓋成C17而沒有衝突提醒。來源明確房間優先，參考應只補缺；衝突留待核對。另GTP8：BSC07-01-1亦被指定C17，應揭露GTP／BSC前綴不一致，不能盲套對照。

跨廠／跨年份／跨方法／未知點位均已有邊界核對，未知者保持待對照。SHA不符、格式錯誤與一般同版no-op沒有發現資料覆蓋；未修改草稿省略列保留作廢，人工修改與已確認列保留。這些通過項目不抵銷上列缺陷。

## 退回驗收要求

Luna 在同一分支修正五項，加入可重現這些失敗的針對測試（須驗歷程內容、實際更新與標示，不能只驗HTTP成功）。重跑必要完整測試，再唯讀核對七份指定來源未退步，更新原交付文件的判定與限制。主對話再次独立驗收前不得宣稱C3／C5／C6／C7通過、不得推送或改寫正式資料。

維持目前Flask／SQLite及清晰固定規則，這是原工單的正確性修復，不增加新架構、LLM、QA簽核或工時門檻。
