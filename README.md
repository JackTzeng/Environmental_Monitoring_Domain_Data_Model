# Environmental Monitoring MVP

本機可執行的 Flask／SQLite 試用版，提供 Word／Sheet 匯入、原始明細核對與修正、逐月點位矩陣、逐欄辨認正確率及月報。所有解析、篩選和統計由可檢視的程式碼執行；不使用 LLM 或外部服務。

目前應以本 README 作為實際功能與操作說明。GUI 歷史評估見 [EM-GUI-FEASIBILITY-v0.2.md](EM-GUI-FEASIBILITY-v0.2.md)；它記錄實作前的狀態，不代表目前功能。

## 啟動與停止

在 Windows 專案資料夾開啟 PowerShell：

```powershell
.\Start.ps1
```

啟動腳本使用專案內 `.venv\Scripts\python.exe`，以 Waitress 在 `127.0.0.1:8765` 提供服務，並開啟瀏覽器。停止時執行：

```powershell
.\Stop.ps1
```

第一次使用若尚未建立環境，依既有環境安裝 `requirements.txt` 後再啟動。也可直接執行 `.venv\Scripts\python.exe -m em_mvp.app`；預設網址為 `http://127.0.0.1:8765`。

## 資料與備份

預設資料目錄為 `%USERPROFILE%\Documents\Codex\Environmental_Monitoring_MVP-data`，可用環境變數 `EM_MVP_DATA_DIR` 指定另一個本機資料目錄。目錄包含：

- `em.sqlite3`：唯一系統資料庫。
- `sources\`：依 SHA-256 內容雜湊保存的來源副本。
- `backups\`：每次資料寫入前建立的 SQLite 一致性備份。
- `logs\`：啟動腳本建立的服務記錄與 PID 檔。
- `session.key`：本機瀏覽器工作階段金鑰。

SQLite 資料庫應放在本機磁碟，不放 OneDrive／Google Drive 同步資料夾或網路共用路徑。匯入來源可放在本機或有權限的公司 UNC 共用資料夾。來源文件以副本方式保存，不改寫原檔。

要檢查備份，可用 SQLite 工具開啟 `backups\<時間>.sqlite3`。還原前先停止服務，另存目前的 `em.sqlite3`，再以選定備份取代；保留 `sources\` 來源副本，不要清除。重要資料還原前先在副本驗證資料庫與來源關聯。

## 匯入資料

在「輸入」頁的「匯入整個資料夾」欄位輸入路徑，例如 `C:\EM reports` 或 `\\server\share\EM reports`，按一次「匯入整個資料夾」。程式遞迴掃描子資料夾，預設讀取 `.docx`；勾選後也會讀取 `.xlsx` 與 UTF-8 `.csv` 匯出檔。結果直接進入同一個 SQLite 資料庫，狀態為「待核對」，不需要逐檔挑選或逐筆確認才入庫。來源未標廠別時，可選填匯入廠別脈絡；明確來源廠別優先，若與脈絡衝突會顯示提醒。

頁面顯示掃描目錄、處理進度、新增檔案、新增明細、已存在、略過及失敗清單。單檔上限 25 MB；資料夾總量不受多檔上傳的 25 MB 上限限制。Office 暫存檔、未選取的格式及連結／junction 子資料夾會略過。單檔解析或存取失敗會列出相對路徑與原因，然後繼續處理下一檔。需要讀取 Sheet 時，CSV 必須使用 UTF-8；含 VBA 巨集的 Excel 檔不支援。

輸入頁另有「管理者 Google Sheet 核對」入口，只讀取「三廠管理者更新」及「一廠管理者更新」兩個指定分頁，可匯入本機 XLSX。XLSX 必須同時包含兩張指定分頁；只有確認是完整快照時，才可依 N 空白、O=0 且無菌種子列提出總 CFU 0 候選。對帳先顯示 Word 唯一候選、差異及 draft 候選；空欄補值須再次經資料版本檢查，且不覆蓋人工修改、已核對欄或核對狀態。Sheet 不會被回寫，刪列只提示，不自動刪除原紀錄。正式 OAuth、refresh token 與 Google API 串接尚未驗證；目前可驗收路徑是本機 XLSX 匯入，詳見[合成預覽指南](docs/acceptance/EM-MVP-preview.md)。

重跑時以來源檔案內容雜湊判斷是否已存在；相同內容不新增資料，也不覆蓋人工修正。不同來源檔即使內容相同也不會重複入庫；不同內容但可能是同一採樣的資料會保留，並沿用現有候選提醒。背景工作的狀態只存在目前服務程序記憶體；服務中斷後重新指定同一資料夾即可續做，雜湊會避開已完成的檔案。

輸入頁的「已匯入來源與重新解析」可在 parser 升級後重讀已保存來源副本。系統先備份資料庫，再以來源雜湊驗證副本；原始辨認值與來源 parser 版本保留。只自動補入未被人工修改或核對的草稿欄位；人工值及已確認紀錄不覆蓋，候選差異和版本寫入歷程。新版不再產生的列會保留並標記作廢或待核對，不會硬刪。重新解析目前每個來源檔最多 25 MB。

仍可使用同頁「選取檔案」進行多檔上傳，該方式整個 HTTP 請求仍限制 25 MB；也可新增空白紀錄後人工輸入。

## 資料庫與月矩陣

「資料庫」頁預設開啟資料最新年度的 1–12 月點位矩陣，並含所有非作廢資料；待核對資料會標籤提示。可依年度、廠別、監測類型、方法與核對狀態篩選。矩陣按廠別／監測類型／方法／房間分段，列出點位、Grade、Alert／Action 原文與 12 個月份。

每個月格顯示該分組最早採樣日期的**目前值**，不做月總和，且選取依採樣日期而非匯入順序。最早日期有多筆且值或限值不同時，主格顯示「需核對」；所有候選仍可在點開的月明細中查看。當月其他日期出現同日衝突時也會顯示提醒。判色只使用該月代表紀錄同筆來源的 Alert／Action 原文：超 Action 顯示紅色「行動」，否則超 Alarm 顯示黃色「警戒」；正常不加底色。`<5` 在 5 起算超限，`≤5` 與裸數 5 在大於 5 才算超限。限值未知、缺漏或最早日衝突以中性「需核對」呈現；月格提示會列出代表日期、來源及限值原文。年度列出的限值僅供參考，不用來判當月顏色。

數值 `0`、無採樣 `—`、TNTC、`<1`、N/A、缺值及未知文字分開顯示；折線只連接可計數的最早日結果。點月格可查看該點位當月全部日期、目前值、原始辨認值、核對狀態、來源檔與提醒，並進入現有修正頁。點「原始明細」可切換逐筆列表，亦可匯出 CSV。

匯入資料保留原始辨認值與內容雜湊。修改時填寫原因，歷程記錄前後值；欄位只有人工標記核對後才納入該欄正確率。未核對欄位顯示待核對／未評估，不會自動勾選。未確認的匯入資料不進正式輸出。

## 輸出與既有規則

「輸出」頁與下載的 HTML 報告仍只使用「已確認」紀錄。保留既有點位 CFU 月加總、人員 CRR 與逐欄正確率規則；這些口徑不同於資料庫預覽矩陣的「每月最早值」。`/accuracy.csv` 匯出逐欄核對統計，`/records.csv` 匯出原始明細與追溯欄位。

正確率只依已人工核對欄位計算；未取得全歷史逐欄核對前，不代表全歷史解析正確率。人工新增紀錄不納入解析器正確率。

## 維護與已知限制

- 解析器為固定規則與表格標頭對應；未知 Word 版型、掃描影像、舊 `.doc` 與無法解析的檔案會回報失敗，不做 OCR 或推測。
- app `0.4.0`／parser `0.1.4` 增加 C01–C06（含字母子房間）一廠分類、受支援 mold／satellite 括號結果總 CFU 解析、依每月代表來源限值提示超限，以及舊來源批次保護式重新解析。既有廠別／方法／年份限定的房間參考對照仍僅支援已核對的 2026 三廠落菌法 15 點，不推廣至其他範圍。
- XLSX 使用唯讀解析；含巨集檔會拒絕。Sheet 欄位無法辨識或來源欄位互相衝突時，需要人工核對。
- 本工具是單機試用版，服務只綁定 localhost；沒有帳號、多人併發服務、QA 簽核、電子簽章或法規驗證聲明。
- 同一服務程序同時只執行一個資料夾匯入。重複啟動會顯示現有工作；背景狀態不跨服務重啟保存。
- 上傳及本機路徑資料均不會送到外部服務；資料庫、來源及備份由使用者依公司資料保留政策管理。
